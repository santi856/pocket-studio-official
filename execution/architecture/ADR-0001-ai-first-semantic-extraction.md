# ADR-0001 — AI-First Semantic Extraction, with a Scope-Frozen Deterministic Fallback

**Status:** Accepted.
**Date:** 2026-07-18.
**Decision record:** D-0079/EV-0124. **Supersedes no prior ADR** (this is the first ADR in this repository).
**Governing inputs:** `execution/architecture/SEMANTIC_PRODUCT_COMPILER_REPORT.md` (pre-implementation design), `execution/architecture/SEMANTIC_PRODUCT_COMPILER_COMPLETION_REPORT.md` (completion report, §4 Capability Boundaries, §6 Remaining Technical Debt, §7 Recommended Next Milestone), D-0065 through D-0077 / EV-0110 through EV-0122 (the full semantic-hollowing repair and its 7 independent Level 3 review rounds).

---

## Context

`src/lib/ai/provider.ts` defines `AIProvider.extractProductSemantics()` with two implementations:

- `AnthropicAIProvider.extractProductSemantics()` (`src/lib/ai/anthropic-provider.ts:487`) — the intended real path. Makes a live Anthropic Messages API call with forced tool-use; on request failure or a malformed response, after its retry budget, falls back to the same deterministic heuristic `MockAIProvider` uses.
- `MockAIProvider.extractProductSemantics()` (`src/lib/ai/mock-provider.ts:51`) — unconditionally calls the same deterministic heuristic.

Both paths, in the fallback/mock case, resolve to `extractSemanticsHeuristically()` (`src/lib/ai/heuristic-extraction.ts`) — a hand-rolled, regex-based, language-generic (no per-domain vocabulary) extractor. Its own module docstring has always described it as "a genuine, disclosed, reduced-intelligence mode," never a second attempt at AI-level understanding.

Two facts, both independently verified rather than assumed, motivate this ADR:

1. **`AI_PROVIDER=mock` is this repository's own default** (`.env.example`), and no live Anthropic credentials are configured in this build. `AnthropicAIProvider.extractProductSemantics()` is real and structurally correct but has never been exercised against the live Anthropic API in this build — only against a scripted fake response in tests. This means the mechanism intended as the _fallback_ is, for ordinary usage today, actually the _primary_ path a real user's traffic would hit.
2. **The deterministic fallback has absorbed seven consecutive rounds of independent Level 3 adversarial review**, each finding a genuine, live, reproducible defect in the same mechanism: rounds 1–4 closed a convergent vocabulary-corruption problem (a modal, then a function word, then an unlisted adverb getting swallowed into a captured actor name), resolved by a positive allowlist. Rounds 5–7 each found a new, _unrelated_ syntax-handling gap producing the same "false zero-actor hard block" symptom (sentence-position anchoring; case-sensitive role-suffix matching; then, in round 7 alone, four more: a semicolon clause boundary, a hyphenated compound actor name, a bulleted/dash-prefixed role list, and a comma-less leading subordinate clause — three fixed, the fourth deliberately disclosed and left open, D-0075). Round 7's own explicit, requested assessment — reaffirmed by D-0077's independent re-verification — is that this class of finding is **not converging**: a regex-based clause/pattern matcher enumerating punctuation and syntax cases one at a time has the same non-convergence property that the earlier word-blocklist approach did, and for the same underlying reason (natural-language structure is not a small closed set either).

Continuing to invest adversarial-review and patching effort into the deterministic fallback, while the mechanism actually designed to be primary has received comparatively little scrutiny, is a misallocation this ADR exists to correct.

## Decision

1. **Real AI-backed extraction (`AnthropicAIProvider.extractProductSemantics`) is the architecturally intended primary path for semantic understanding**, not the deterministic heuristic. This was already true by design (the heuristic's own docstring has said this since it was written); this ADR makes it an explicit, binding architectural decision rather than an implicit assumption, and ties a concrete next milestone to it (see Consequences).
2. **`heuristic-extraction.ts` is retained permanently as a disclosed, deterministic fallback** — used when no live provider is configured, and when a live call fails after its retry budget — never removed, because a fallback with honest low-confidence provenance is safer than no extraction at all or a hard failure of the generation pipeline.
3. **`heuristic-extraction.ts`'s syntax-handling scope is frozen as of this ADR**, at the capability boundary already documented in `SEMANTIC_PRODUCT_COMPILER_COMPLETION_REPORT.md` §4: it reliably handles single-sentence, comma/semicolon/and/but-joined, hyphenated-or-not actor phrasing, in either common-noun capitalization convention. It is not to be further expanded merely to chase an additional newly-found syntax construction (a new punctuation mark, a new clause-boundary word, a new capitalization convention, etc.). The disclosed, known-open gap (a comma-less leading subordinate clause) stays open under this freeze, by the same reasoning D-0075 already recorded: the two available ways to close it were tested and rejected as introducing a real corruption risk worse than the disclosed miss.
4. **The freeze has one carve-out: genuine corruption is still a bug, not a scope question.** If a future finding shows `heuristic-extraction.ts` producing a _corrupted_ (wrong, not merely absent) actor/entity/workflow name — as opposed to a clean miss backstopped by the existing zero-actor Quality Gate check — that remains an in-scope defect to fix under the existing repair discipline, because corruption is a correctness failure this file's entire design history (rounds 1–4) has treated as categorically worse than a disclosed miss. A missing syntax construction is not, by itself, grounds to lift the freeze.
5. **No further independent Level 3 review round is to be spawned against `heuristic-extraction.ts`'s syntax coverage specifically**, consistent with D-0075/D-0077's judgment that this has stopped being a converging process. Review effort for semantic extraction should redirect to validating `AnthropicAIProvider.extractProductSemantics()` against the live API instead (see Consequences item 1).

## Consequences

1. **Concrete next milestone (already named in `SEMANTIC_PRODUCT_COMPILER_COMPLETION_REPORT.md` §7, now binding via this ADR):** exercise `AnthropicAIProvider.extractProductSemantics()` against the real Anthropic API across the existing multi-domain corpus (9 fixtures + the novel holdout + the phrasing-diverse regression set) to establish real-world accuracy, cost, and latency figures that do not yet exist anywhere in this codebase. Only after that evidence exists should `AI_PROVIDER`'s default value be reconsidered.
2. **`AI_PROVIDER=mock` remains the default until that evidence exists.** This ADR does not change the default itself — doing so without live-API evidence would trade a known, disclosed, capped-scope limitation for an unknown one.
3. **The Quality Gate's hard "zero actors for a substantial description → block" behavior (D-0072) is unchanged by this ADR.** `SEMANTIC_PRODUCT_COMPILER_COMPLETION_REPORT.md` §6 item 6 separately flagged whether this should remain a hard block versus a strong non-blocking warning, given the now-demonstrated width of the fallback's false-positive surface — that is a distinct product-policy question this ADR does not resolve, and is called out here so it is not lost.
4. **Documentation impact:** `heuristic-extraction.ts`'s module docstring and `SEMANTIC_PRODUCT_COMPILER_COMPLETION_REPORT.md` already describe the fallback's disclosed, reduced-intelligence status accurately; no correction is required there. Future PRs touching this file should treat an unfamiliar syntax construction producing a clean miss as expected, disclosed behavior, not an automatic defect to patch.
5. **No code changed as part of this ADR.** This is a documentation/decision artifact only, consistent with its role as the record of a direction already implied by the existing design and by D-0075/D-0076/D-0077, made explicit and binding.

## Alternatives considered

- **Keep patching `heuristic-extraction.ts` syntax coverage indefinitely, one review round at a time.** Rejected: three consecutive rounds (5, 6, 7) each found new, unrelated root causes, the last finding four in one pass — direct evidence this does not converge the way the rounds 1–4 vocabulary fix did. Continued patching would keep consuming review effort for shrinking, and possibly non-shrinking, marginal coverage gains.
- **Remove the deterministic fallback entirely, and hard-fail generation when no live AI provider is configured or a live call fails.** Rejected: this converts a disclosed, honestly-labeled reduced-intelligence result into a total outage for any user without a configured API key (which is this repository's own default state today), a strictly worse customer outcome than a disclosed low-confidence result backstopped by the Quality Gate.
- **Change `AI_PROVIDER`'s default to `anthropic` immediately, as part of this same ADR.** Rejected: no live-API accuracy, cost, or latency data exists yet for this path in this build. Changing the default without that evidence would be exactly the kind of unverified claim this initiative's review discipline exists to prevent.
