## Orphan implementations (real code, no traceable Master Spec requirement)

- `store-readiness.ts`'s per-dimension Truth Status split (`quality.structural` etc.) — a genuine improvement, but not itself named anywhere in the Master Spec (§55 asks for "platform-specific Truth Status," which this generalizes beyond what was literally asked; a reasonable, in-spirit extension, not scope creep for its own sake, given it directly serves §8's "Customer Experience Standard" honesty requirements).
- The Example App Ideas picker — this _is_ explicitly named, but only in `execution/state.json`'s own `architecturalStandards` entry (a build-process artifact), not the Master Spec itself. Its ultimate justification traces to §6 Simple Mode's general "understand what Pocket Studio inferred" / practical-completeness principle (D-0022), not a literal spec line item.

## Requirements with no implementation (within Phase 1/2 scope)

- Interactive Runtime "selectable list item" — no interaction-contract state models this, so nothing implements it. Named honestly in Part 4/5 rather than silently absent.
- §44's "explicit customer approval before accepting marketplace agreements, submitting production applications" — the approval-_requirement_ side is real (Store Readiness never auto-proceeds), but there is no UI flow for a customer to actually grant that approval yet, since there is nothing to submit to (no developer-account integration exists). Correctly deferred, not a gap within Phase 2's own scope.

## Requirements marked complete without sufficient evidence (found by this audit)

- `generation.full_stack_web_app`, `generation.mobile_app`, `governance.legal_document_drafts` in the Capability Registry seed data — all three were carrying a **stale** `implementationLevel` that understated real, shipped Phase 2 capability (the opposite direction of overstatement, but still a real "Truth Status collapsed to one misleading value" instance, per this audit's Part 4/11). Corrected in the uncommitted repair; independently re-verified via a new integration test this session confirming the corrected values seed and query correctly.
